`RadCluster_2_1/digital_twin/learn.py` ranks calibration rows on
`n_in_range_verified` **first**: an unverified row cannot take the top slot no
matter how many target bands it sits in. The gate is deliberate — a `d_cavity`
grid artefact (`d = 0.2825*(0.37V)^(1/3)`) once led the leaderboard for twelve
stages — but it is silent, and it made the campaign look stalled when it was not.

**Why this matters:** as of 2026-09-05 the gated headline reports row **7700**
(2/6 in band, log-distance 0.65) while row **9305** — the workbook default and
the vector behind the reference run — scores **4/6 at log-distance 0.236** and is
simply `UNVERIFIED` (no second-extent pair exists yet). Reading `best` alone and
reporting it as the state of the campaign is wrong; I did exactly that once.

**How to apply:**
- `calibration_ledger.json` now carries **both** `best` (extent-verified) and
  `best_raw` (verification gate removed). `CALIBRATION_GUIDE.md` renders both,
  the second under "Best row ignoring verification". Read both before
  characterising progress.
- `best_raw`'s tie-break deliberately omits `worst_margin`, unlike `best`'s.
  `_margin_or_none()` measures only observables that are *both* verified and in
  band, so it is structurally `None` for exactly the rows that leaderboard exists
  to surface — including it re-creates the suppression.
- Do not treat `best_raw` as a result. To promote row 9305 properly it must be
  re-run at a second V extent. Its `d_void` (5.61 nm vs a 2.12–2.9 band) is
  precisely the grid-readout artefact the gate guards against.
- Both files are regenerated by `python learn.py`; never hand-edit them. Durable
  notes go in the ledger's `notes` key, which survives regeneration.
- See [[project_reference_run]] for what row 9305 is.
